# Can Pops calculate position-player WAR internally?

October 18, 2026. **Yes, the aggregation is straightforward; exact historical FanGraphs WAR is not reproducible from our retained data alone.** We can calculate batting and several adjustments from past events. Measuring fielding, catcher skills and non-steal baserunning is the substantial missing work. A provider-component assembler is credible; rebuilding those measurement models from scratch is a separate research project. This is feasibility, not approval to change P05 or run a model.

## Component map and chronology

The [published WAR framework](https://library.fangraphs.com/war/war-position-players/) is `(batting + baserunning + fielding + positional + league + replacement runs) / runs per win`. Its older UZR/baserunning/catcher examples are superseded by later updates. Use the [2024 methodology change](https://blogs.fangraphs.com/2024-fangraphs-war-update/) and current component documentation when fixing a version.

| Component | Retained inputs and feasible calculation | Missing inputs / exactness boundary |
| --- | --- | --- |
| PA and batting events | Sum per-game `b_pa,b_ab,b_h,b_d,b_t,b_hr,b_w,b_iw,b_hbp,b_sf` strictly before cutoff; singles = H−2B−3B−HR. Can reconstruct event counts and weighted on-base production, with explicit interference/sacrifice rules. | Exact agreement needs count reconciliation and the chosen wOBA event weights, league mean/scale and version. No new learned batting model is necessary for fixed linear weights. |
| Batting runs | Compute wRAA from wOBA, league mean/scale and PA; apply chosen park and league scoring adjustments. | Current-season final weights, league R/PA and non-pitcher league rates contain later games. Use verified pre-season constants or expanding prior-only totals with a preseason initialization. Neither automatically reproduces original daily fWAR. |
| Steal value | SB/CS and opportunity counts are retained; a [wSB-style calculation](https://library.fangraphs.com/offense/wsb/) is reproducible with frozen run weights/league baselines. | Correct scoring attribution, pickoffs and league opportunities must reconcile. This is only part of baserunning. |
| Other baserunning | Runner advances/base-outs permit an internally defined transition/run-expectancy measure. | FanGraphs' revised XBR requires opportunity-quality inputs. MLB's [extra-base metric](https://baseballsavant.mlb.com/leaderboard/baserunning) uses runner speed, positioning and outfielder distance/arm, including opportunities declined. Retained event outcomes do not supply those expectations. Need dated provider XBR or a separately approved, prior-only learned/empirical approximation. |
| Non-catcher fielding | Defensive outs and position are retained; putouts/assists/errors describe outcomes. | Range difficulty, starting position, time/distance, throwing opportunities and provider expected-outs/run credits are missing. Cannot derive Statcast range/arm quality from these counts. Need dated provider component runs/opportunity probabilities; coarse location-based estimates would define a different metric and require validation. |
| Catcher fielding | Catcher identity/exposure and PB/WP/SB/CS outcomes are retained. | Framing needs taken-pitch location/call/context and an expectation model; blocking needs pitch difficulty, not just PB/WP; throwing needs opportunity/pitcher/runner context. These are not recovered by assigning all failures to the catcher. See detailed boundary below. |
| Positional adjustment | `d_ifouts/3` gives innings by defensive position. Apply a frozen published run-per-position schedule to that actual past exposure, summing positions. This is a modest deterministic calculation. | DH is absent from fielding positions 1–9; derive DH exposure using batting/lineup/substitution records and audit mixed DH/fielding/pinch-hit games. Do not treat every game appeared as nine defensive innings or use the prorated date-filter Positional field. |
| League adjustment | A league-wide centering calculation can be defined from complete prior-only component totals and PA, or a frozen previous-year per-PA adjustment. | Exact fWAR centering depends on all league players' other components, including missing defense. Hitting-only totals cannot reproduce it. Frozen adjustment is an explicit approximation. |
| Replacement adjustment | Apply a declared replacement-runs-per-PA rate to prior PA; alternatively evaluate the published replacement pool formula with prior-only MLB games/PA and runs-per-win. Team game counts/PA/outs/runs are retained. | Final season games/PA/runs-per-win must not be used for early dates. Previous-year rates are feasible but are our convention; early-season recalculation needs initialization and fixed rules. |
| Runs per win | Estimate the run environment from retained league runs and innings/outs using a fixed formula, or freeze a previous-year constant. | A fixed 10 runs/win is an approximation. Final current-year runs/innings is future information. Exact daily provider constants/publication vintage are not retained. |
| Park effects (within batting runs) | `site`, team and game exposures support joining a published park table, or a past-only park estimate. | No verified as-of park-factor table is retained here. Published multi-year factors can use later seasons or later revisions. Need vintage evidence, a genuinely backward-looking estimate, or an explicitly neutral approximation. Prior-year *label* alone does not establish that a factor was available then. |

FanGraphs' [Guts constants table](https://www.fangraphs.com/tools/guts?type=cn) provides public annual weights, R/PA and runs/win. It is an obtainable input lead, not proof those current retrospective values were published before a historical target. For training starting in 2022, freezing prior-year constants introduces a 2021 constants/park/advanced-component dependency that the existing current-season-only P05 did not otherwise need.

## Defense and catchers: assembling measurements versus inventing them

The [Statcast fielding-run-value page](https://baseballsavant.mlb.com/leaderboard/fielding-run-value) publishes run conversions and component leaderboards. This makes importing provider-measured components and summing them internally plausible. It does not make all underlying tracking or per-play model outputs available in the standard [Statcast CSV schema](https://baseballsavant.mlb.com/csv-docs). That schema has useful pitch coordinates, catcher IDs and batted-ball variables; those alone are not the complete input set for reproducing all provider defensive algorithms. Exact-day export coverage, revisions, publication timing and stable identity must be tested on a small sample before an acquisition plan.

For catchers, [blocking documentation](https://baseballsavant.mlb.com/leaderboard/catcher-blocking) describes expectations based on pitch location, velocity/movement, catcher location and handedness. Counting successful blocks without difficulty/opportunities would reward easy pitches and conflate pitcher with catcher. Framing requires distinguishing a likely strike from an extra strike earned; throwing likewise needs an opportunity/context baseline. Importing MLB's total FRV still does not prove fWAR equivalence: FanGraphs staff explicitly state in the 2024 update's comments that their framing uses **Jared Cross's metric**, rather than Statcast framing. The current MLB FRV page also includes double-play and first-base receiving components; adding everything shown there would silently change the selected FanGraphs definition. Select and reconcile components, not a convenient aggregate.

Building our own framing/range/blocking/throwing models would require new data, estimated expectations, train-only fitting/calibration and a separate evaluation. This task has fitted none. Published run conversions do not eliminate that measurement-model problem.

## Three credible paths and effort

1. **Internal assembly of provider components — recommended first.** Retrosheet supplies counts/exposure; a dated provider source supplies the difficult defensive/baserunning measurements; verified constants supply adjustments. This avoids relying on the leaking custom-date aggregate while keeping a traceable breakdown. A small component-readiness probe is plausibly 1–2 focused workdays; after admission, deterministic assembly/reconciliation is several further workdays. These are engineering estimates, not a guarantee or an approved time budget. Exact fWAR still needs component/version agreement, especially framing, and original as-of claims require publication evidence.
2. **An explicit Pops WAR-like estimate.** Past-only batting/steal values, actual position exposure, frozen prior-year constants/parks plus a declared preseason or previous-year defensive/baserunning estimate could produce an all-around estimate without current-season tracking. It combines observed and estimated contributions; it is **not raw observed WAR**. Prior-year quality must be auditable before the target; do not infer separate observed defensive runs from total projected Def. A basic version is days of engineering plus validation once the definition is agreed. It changes P05's raw/blended representation and needs Tom's decision, not an automatic fallback.
3. **Rebuild advanced measurement from raw tracking.** Potentially feasible as independent research, but weeks or longer with no assurance of matching fWAR or improving winner probabilities. Data availability/model vintage, catcher attribution and calibration dominate. This is disproportionate as the immediate route for a small paper-alert prototype. Basic error/putout rates or zero defense are not acceptable hidden substitutes.

## Validation before any winner fit

A bounded component audit should use a catcher, an infielder and an outfielder at an early-season, mid-season and full-season cutoff. Reconcile IDs/PA/hit counts, defensive outs by position and component units/signs against independent official totals. Resolve Retrosheet `stattype` variants (`value/official/lower/upper`) and duplicate contribution keys before summing. Validate DH and position changes, transfers, debut/zero PA and missing data. Record component differences rather than hide them in a matching total. Full-season fWAR is an accounting comparison only, never an input to earlier estimates or a target used to tune early inputs.

Use the existing prior-New-York-calendar-day rule: no same-day games, including doubleheader game one. Separately resolve resumed/suspended source games—an original game date can precede later completed events. Preserve the existing resumed-target exclusion and do not assume it solves source-history chronology. Pin source versions and timestamp provenance; later corrections to earlier events are a qualified retrospective reconstruction unless historical availability is proved.

A key future test is prefix invariance: appending/changing later games or a later constants table must leave an earlier computed value unchanged. A prior-only measurement model must freeze training data/model version before its cutoff. At season start define initialization; never fill missing advanced components with zero and label them measured. Coverage must include all required historical lineups and failure counts. Before any six-arm execution, independent review must accept the final definition, components and chronology against [PROTOCOL.md](PROTOCOL.md).
