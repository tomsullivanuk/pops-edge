## Owner readability amendment — September 13, 2026

All readable principal, historical and expandable detail metrics use at most two
decimal places; counts remain integers and times use friendly dates without
fractional seconds. No calculation, probability, canonical identifier or scientific
payload is rounded. Comparisons must acknowledge displayed ties without implying
exact equivalence; rounded interval endpoints must not imply certainty.

Every drill-down uses readable prose, labelled tables, calendar date ranges and
named report links. Calendar details distinguish verified, unverified and empty
states without inferring missing-game counts. Saved-report/update details distinguish
no selection, no attempt, success, running and failure, retaining earlier-report
status truthfully. Exact records, identities, timestamps, rules and reproduction
metadata remain in labelled technical downloads, never inline machine-record dumps.

Renderer `mlb-reporting-html-3` implements this amendment. The original v1 and v2
renderers remain available for byte-exact replay of immutable packages. A separately
dated, explicitly non-authoritative presentation of previously verified acquired
results may be created without rescoring or source acquisition. It links the
unchanged original evidence and verification receipts and records renderer hashes.
The existing acquired-data entry is a read-only reference for this correction;
no new display-pointer publication contract is introduced. Local display edits and
preview creation are authorized; new commit, push, PR, merge or deployment are not.
