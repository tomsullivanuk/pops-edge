# Pops' Edge v1.1.0 Checkpoint Through PR6

## 1. Purpose

This checkpoint records the implemented and validated Pops' Edge platform
baseline after PR6 and before MLB market reconciliation and valuation begin.
It gives future contributors and planning conversations a concise entry point
to the contracts, provider boundaries, proven evidence path, and constraints
that subsequent work must preserve.

v1.1.0 remains unreleased. This document is neither a release nor a tag, and it
does not change version numbering. PR7 through PR10 remain planned in
`docs/RELEASE_PLAN_v1.1.0.md`; repository product, architecture, developer, and
release documentation remains authoritative when more detail is required.

## 2. Product capability now proven

The implemented platform path is:

```text
External facts
        ↓
Canonical Event identity
        ↓
Immutable observations and provenance
        ↓
External forecast reconciliation
        ↓
Forecast Series and history
```

Pops' Edge can now:

- collect bounded MLB facts through the MLB Stats API adapter;
- preserve exact raw-source and canonical-evidence SHA-256 digests;
- construct authoritative MLB Canonical Events using MLB-native identity;
- represent immutable schedule, status, and pitcher observations;
- parse faithful, manually captured DRatings Upcoming-table HTML snapshots;
- preserve both published win probabilities exactly, including their displayed
  representation and precision;
- preserve provider-reported starting-pitcher assumptions separately from MLB
  facts;
- reconcile forecast rows to MLB events using controlled aliases, participant
  identity, and exact UTC schedule evidence;
- create deterministic Forecast Series lazily with their first valid Forecast
  Observation;
- append immutable Forecast Observations to Forecast History; and
- derive latest/current forecast state without rewriting historical evidence.

Market observations, market reconciliation, valuation, edge calculations, and
recommendations are not implemented for MLB.

## 3. Durable architecture

The platform separates:

```text
Identity
Evidence
Policy
```

Time-varying evidence follows:

```text
Durable Identity
        ↓
Immutable Observations
        ↓
Derived Views
```

Implemented domain concepts include Canonical Event, sport-native identifiers,
provider source mappings, Forecast Provider, Forecast Model, Forecast Version,
Forecast Series, Forecast Observation, Forecast History, provenance,
reconciliation, structured validation, and explicit complete, partial,
ambiguous, and rejected adapter outcomes.

Identity is immutable. Evidence is immutable and append-only. Latest/current
state is a derived view rather than stored mutable evidence. Ambiguous or unsafe
identity fails closed. Policy may evaluate evidence, but it must not rewrite
identity or historical observations.

## 4. Provider boundaries

### MLB Stats API

The MLB Stats API supplies MLB-native game identity, authoritative team
references, schedules, statuses, probable pitchers, and the independent facts
used during event reconciliation. It is currently appropriate for this
personal, noncommercial hobby project. Its contracts remain behind a
replaceable provider adapter rather than making the source a universal domain
dependency.

### DRatings

DRatings is the first external forecast provider. The implemented identity uses
the provider-published Inference Index model name and an explicitly unknown
model version. Upcoming rows publish complete two-outcome win distributions and
provider-reported pitcher assumptions.

PR6 accepts only faithful, manually captured local HTML snapshots. Automated
DRatings collection is not implemented or approved. DRatings does not supply
MLB `gamePk`, authoritative MLB team or pitcher identity, row-specific forecast
timestamps, a disclosed version, or a proven stable forecast-record identifier.
MLB identity and away/home roles come from separate MLB evidence. The DRatings
adapter is replaceable and contains its provider-specific parsing and aliases.

## 5. Source truth and provenance

Normalized output remains traceable through the applicable source URL, a
separate access URL when different, collection or capture timestamp, exact raw
response/file SHA-256, canonical evidence digest, parser or adapter version,
deterministic source-row locator, transformations, and structured validation
issues.

For example, the approved DRatings fixture preserves a manually captured HTML
file and its parsed Upcoming rows, while the separate MLB fixture preserves the
authoritative schedule response used for reconciliation. The fixtures
demonstrate the evidence model; they are not persistence infrastructure or
permission for automated provider access.

## 6. Fail-closed and partial-success behavior

Valid identity can survive missing optional evidence. For example, absent
provider assumptions or optional source metadata can produce a partial,
incomplete observation after unique event reconciliation. A timestamp that the
provider does not publish is kept unknown rather than fabricated and does not,
by itself, invalidate otherwise complete published evidence.

Malformed distributions, conflicting identity, unmatched rows, and ambiguous
candidate events produce no authoritative event selection, Forecast Series, or
Forecast Observation. Raw evidence, candidate evaluations, and structured
issues remain available for audit. The adapters perform no fuzzy forced match,
best-guess identity repair, normalization, or silent source correction.

## 7. Regression baseline

Subsequent PRs must preserve:

- existing World Cup v1.0.0 production behavior;
- Canonical Event and sport-native identity contracts;
- Forecast Observation contracts and precision-aware validation;
- MLB Stats API adapter contracts;
- Forecast Series identity and append-only Forecast History;
- faithful DRatings Upcoming-table parsing and source-order preservation;
- deterministic serialization and fixture-backed offline tests;
- no import-time network activity; and
- confinement of provider-specific behavior to adapters.

The validated checkpoint result after PR6 was **135 tests passed**. This records
the checkpoint result, not a permanent expected test count.

## 9. PR7 entry conditions

PR7 must assume that Canonical Event identity already exists, while MLB facts
and forecast evidence remain separate immutable records. Forecast Series and
Forecast Observations must not be rewritten to accommodate market data.

Market evidence must enter through an equivalent provider boundary. Market
observations must remain separate from forecast observations, and valuation
must be derived from the two evidence sets. Recommendation and sizing remain
policy. Ambiguous market/event/side reconciliation must fail closed. Existing
World Cup behavior remains unchanged unless a separate scope explicitly
authorizes and validates a change.

This checkpoint states those entry conditions without designing PR7.
