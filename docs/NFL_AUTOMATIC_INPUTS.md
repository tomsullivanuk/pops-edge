# Automatic NFL input discovery

The Owner approved automatic latest-file discovery and the compact update screen
on November 12–13, 2026. Implementation supersedes manual file selection in the
NFL browser workflow. This does not authorize deployment, research activation,
provider acquisition outside an explicit update, or retrospective Evidence repair.

## Workflow and authority

Configure one existing directory with --inbox. Use the host user's iCloud Drive /
PopsEdge/Downloads/NFL for the shared workflow. Archives, activated performance
data, and report settings remain under the existing --root. The historical local
inbox default remains available for compatibility. No browser request configures
a directory or uploads a file.

The page automatically lists the newest saved ELWAY workbook, Kalshi All Activity
and realized P&L export once, with filenames and saved timestamps. Refresh Bet
Sheet uses workbook plus All Activity. Update accounting uses the same discovery
of All Activity plus realized P&L, without price requests. Missing P&L alone does
not block a Bet Sheet refresh. Each explicit action rescans before using files.
Opening the page, gaining focus and Check for new files do not import or acquire
provider data or initialize research stores.

Newest means greatest filesystem modification time. This is local saved-copy
recency, not publisher chronology, file creation time, import time or a filename
ordering. It never establishes scientific publication-time authority. Existing
ELWAY published/proxy-time validation and weekly eligibility/cutoff rules remain.
A recently edited old file may be selected; the name and saved time remain visible.

All .xlsx files in this dedicated NFL inbox are workbook candidates. Existing
ELWAY validation still runs before acquisition. CSV column headings distinguish
All Activity and P&L even after renaming. Familiar Kalshi export filenames keep
malformed newest inputs visible as invalid candidates; unrelated CSVs are ignored.
Tied newest saved times block the affected action, even for duplicate bytes;
keep one latest copy in the folder to resolve the tie. Invalid newest recognized
inputs never silently fall back to older valid copies. File byte fingerprints
reject changes between discovery and use. Automatic refresh receipts record
the selected metadata and selection rule; immutable source archives remain.

## Acceptance boundary

Must hold: no required file picking; one shared activity discovery; only explicit
updates acquire/import; required inputs unambiguous; changed-file rejection;
visible missing/unreadable-folder and invalid-input failures; unchanged Evidence
chronology, baseline eligibility and local archives. No empty fallback directory.
Running, completed and failure feedback stays visible near the update buttons;
active weekly baseline checks remain visible. Technical/help and inactive-capture
status may be collapsed. A readable iCloud copy does not prove sync completeness.

Accepted limitations: sync/download delay and manual Keep Downloaded setup, local
mtime rather than vendor publication ranking, manual removal/replacement of bad
or tied inputs, existing file size limits. Deferred: automatic ingestion or
acquisition, sync service, vendor ranking, generalized upload and MLB redesign.

One focused implementation with its documentation is sufficient. The Mini's
existing pinned-runtime and optional local uploader/launcher customizations must
be inspected before integration/deployment there; do not overwrite a live pin.
